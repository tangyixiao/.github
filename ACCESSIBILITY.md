# Accessibility

Project documentation and interfaces should be usable with a keyboard, readable at enlarged text sizes, and understandable without relying on color alone. Images that convey information should have useful text alternatives. Motion should respect reduced-motion preferences when practical.

These are implementation goals, not a claim that every inherited project is already compliant with an accessibility standard.

## Report a barrier

Open an issue in the affected repository. Describe the page or feature, the task you tried to complete, the observed barrier, and the browser, operating system or assistive technology involved when relevant. Screenshots or recordings are optional; do not include personal information. English and Chinese reports are welcome.

For a barrier in the shared standards or their site, use [tangyixiao/.github Issues](https://github.com/tangyixiao/.github/issues). If a report also reveals a security problem, use [private security reporting](https://github.com/tangyixiao/.github/blob/main/SECURITY.md).

The maintainer considers impact and available capacity when prioritizing fixes. There is no guaranteed response deadline. A successful automated check does not prove the absence of barriers; state which automated checks and manual tasks were actually verified.
