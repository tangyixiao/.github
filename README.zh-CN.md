# 项目官网与社区模板

[English](README.md) · [完整规范](docs/standard.md) · [接入方法](docs/adoption.md) · [贡献说明](CONTRIBUTING.md)

一份可以换成自己项目内容的官网模板，配套社区入口、贡献流程和维护规范。访客首先看到项目用途、产品画面与使用方式，需要时再进入文档和社区。

当前用 OJ NEXUS 的真实项目信息演示布局。示例不包含它的应用源码或安装包；绘制的界面明确标为布局示意，不冒充实测截图。

## 换成自己的项目

1. 样板合并并启用模板模式后，可用它创建仓库；审查阶段先看 PR 分支，或只把其中官网相关文件接入现有项目。
2. 修改 [`project.json`](project.json)，填入项目名称、介绍、功能、画面和实际使用入口。已有真实截图时，用它替换示意界面，并提供图片说明。
3. 渲染并检查页面：

   ```sh
   python scripts/render_site.py
   python scripts/check.py
   python -m http.server 8765 --directory site --bind 127.0.0.1
   ```

浏览器打开 `http://127.0.0.1:8765`，结束后停止服务。生成后的 HTML 已包含项目内容，关闭 JavaScript 仍可阅读，也可直接打开文件。内容更新通过修改配置、重新渲染完成。

渲染和检查只需要 Python 标准库，无需安装前端依赖、字体或分析服务。详细复制范围、社区联系信息与部署步骤见[接入方法](docs/adoption.md)。

## 这一版包含什么

| 内容 | 作用 |
| --- | --- |
| 社区默认文件 | 贡献指南、行为规范、安全报告、支持、无障碍说明，Issue / PR / Discussion 表单 |
| 项目运营规范 | README、Pages、许可与来源、社区分工、版本发布、恢复、模板升级和实际验收 |
| AI 贡献政策 | 允许 AI 辅助，提交者负责理解修改、验证行为和如实报告证据 |
| Agent 工作规则 | 优先复用工作区，集中临时文件，限制峰值磁盘占用，收尾时保护独有成果 |
| 可复用项目官网 | 集中配置项目内容，生成静态页面；介绍、画面、功能、开始使用与社区路径 |
| 本地与 CI 检查 | 检查配置与生成结果一致、渲染器行为、链接、表单、Action 固定版本和体积 |

当前 PR 中的默认社区文件尚未对其他仓库生效；合并到默认分支后，GitHub 才会使用受支持的默认文件。现有线上 Pages 仍来自独立的 `project-pages` 分支。

## 磁盘空间优先

- 只读检查和小修改优先复用现有目录，避免重复 clone、安装、下载和构建。
- 大量写入前估计峰值：压缩包、解压目录、依赖、构建输出可能同时占空间。
- 临时文件归入本任务 `work/`，日志有界保存，交付物明确保留。
- 任务结束、方案放弃、被打断后恢复时，都检查本任务留下的资源。
- 清理只涉及能确认归属的资源，先保护未提交修改、未跟踪文件和独有提交。
- 同盘移动或放入回收站不代表磁盘空间已经释放。

配置中的预算是默认工作约定，不能代替操作系统权限、磁盘配额或客户端沙箱。确需大型数据或产物的任务，应明确调整预算，避免无意义地重复生成副本。

## 哪些会继承

GitHub 只对受支持的社区文件提供默认回退；项目自己的文件优先，Issue 模板还可能整组覆盖默认模板。这些文件不会自动进入项目的 clone 或发布包。

`LICENSE`、`AGENTS.md`、`AI_POLICY.md`、CODEOWNERS、工作流和平台开关，需要单独接入。这个仓库不会自动控制其他 agent，也不会擅自修改其他项目。

验收分别记录：文件已修改、本地检查、CI、合并、部署、平台设置、实际用户路径。现有功能开关与计划实现的功能要明确区分。
