# Getting help

For help with a project, start in the affected repository. Its README and documentation describe installation, supported platforms and common problems.

| Need | Where to go |
| --- | --- |
| Usage question or an early idea | That repository's Discussions, when enabled |
| Reproducible defect | That repository's Issues |
| Concrete feature proposal | That repository's feature-request issue form |
| Vulnerability or exposed credential | [Private security reporting](https://github.com/tangyixiao/.github/blob/main/SECURITY.md) |
| Shared template, policy or project-standard problem | [tangyixiao/.github Issues](https://github.com/tangyixiao/.github/issues) |

If the affected repository has no Discussions, use its documented help channel or an issue clearly labeled as a question in the title. Check existing answers first. Include the project version, operating system, steps already tried and a small example. Redact tokens, passwords, private URLs and personal information from logs and screenshots.

English and Chinese questions are welcome. These are personal projects; help depends on maintainer and community availability, with no guaranteed response time. Do not open the same request across several repositories or repeatedly ping people. A bug report may be useful even when an immediate fix is unavailable.

This hub coordinates shared standards. It is not a replacement issue tracker for every project.
